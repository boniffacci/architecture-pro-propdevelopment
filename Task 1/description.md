

## 1. Классификация данных

| Категория | Примеры данных в системе PropDevelopment | Доступ | Требуемый уровень защиты |
|------------|------------------------------------------|---------|----------------------------|
| **Публичные данные** | Описание жилых комплексов, цены, фотографии, рекламные материалы, новости и статьи на сайте | Открытый доступ для всех пользователей | Минимальный — защита целостности и достоверности |
| **Внутренние данные** | Внутренние отчёты, инструкции, техническая документация, схемы архитектуры, переписка в корпоративных системах | Сотрудники и подрядчики по NDA | Средний — ограниченный доступ, резервное копирование |
| **Конфиденциальные данные** | Персональные данные клиентов и собственников (ФИО, контакты, паспортные данные, история платежей и бронирований, данные IoT-устройств) | Авторизованные сотрудники, CRM, API партнёров | Высокий — защита по ФЗ-152, шифрование, контроль доступа |
| **Секретные данные** | Финансовая отчётность, юридические документы, токены API, пароли, ML-модели, BI-аналитика | Только руководство, ИБ-отдел, администраторы | Максимальный — шифрование, сегментация сети, аппаратные HSM |

## 2. Определение рисков

| Категория данных | Возможные риски |
|------------------|-----------------|
| **Публичные данные** | Искажение данных, некачественные данные |
| **Внутренние данные** | Утечка данных, потеря данных |
| **Конфиденциальные данные** | Утечка данных, искажение данных, потеря данных |
| **Секретные данные** | Утечка данных, потеря данных, обесценивание данных |

---

## 3. Обоснование актуальности рисков

| Категория | Почему актуально |
|------------|------------------|
| **Публичные данные** | Ошибки или несанкционированные изменения информации на сайте (например, неверные цены или характеристики) могут привести к репутационным потерям и юридическим претензиям. Некачественные данные снижают доверие клиентов. |
| **Внутренние данные** | Утечка технических или организационных документов повышает риск кибератак и конкурентного ущерба. Потеря данных из-за сбоев резервного копирования мешает работе внутренних команд. |
| **Конфиденциальные данные** | Утечка персональных данных клиентов ведёт к штрафам и судебным искам. Искажение или потеря ПДн может нарушить бизнес-процессы и повлечь блокировку операций с клиентами. |
| **Секретные данные** | Компрометация финансовых отчётов, API-ключей или моделей ML может вызвать прямые финансовые убытки. Потеря данных разрушает аналитические процессы. Обесценивание происходит при неконтролируемом распространении моделей и алгоритмов. |

## 5. Ключевые выводы

- Наиболее уязвимы **конфиденциальные** и **секретные** данные.  
- Основные угрозы — **утечка** и **потеря** информации.  
- Необходимо реализовать следующие меры:
  1. Усилить контроль доступа (RBAC, MFA, аудит логов).  
  2. Централизовать хранение персональных данных.  
  3. Реализовать DLP-систему и мониторинг активности пользователей.  
  4. Обеспечить шифрование данных на всех уровнях (в покое и при передаче).  
  5. Провести аудит API-контрактов с партнёрами.  
  6. Настроить регулярное резервное копирование и проверку восстановления данных.
